# Review replies

Public, permanent, and read by future customers. Write for them as much as the reviewer.

## Rules
- Reply to every review, newest first, unanswered first.
- Short. 1 to 3 sentences for positive, up to 5 for negative.
- Sound like the developer, not a support macro. Vary wording.
- Never argue, blame the user, or promise dates you can't keep.
- Never include personal data. Point to a support channel instead.
- If the issue is fixed in a shipped version, say which version.
- If it's a feature request, acknowledge it honestly ("it's on the list" only if true).

## Patterns
**Positive:** Thank them, mention the specific thing they liked.
> Thanks so much! Glad the streak view is keeping you on track.

**Bug, fixed:**
> Sorry about that. This was fixed in 2.4.1, so updating should sort it out. If it doesn't, email support@... and I'll dig in.

**Bug, not yet fixed:**
> Sorry, that's frustrating. I can reproduce it and I'm working on a fix. If you email support@... I'll let you know as soon as it's out.

**Feature request:**
> Great idea, and you're not the first to ask. Noted for a future update.

**Pricing complaint:**
> Understood. The free version covers [core feature]; Pro adds [x] and keeps development going. Happy to answer questions at support@...

## After replying
Tally themes and feature requests and include them in the report.
